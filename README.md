# Afresh

Afresh provides the native statistics interface used by iILS and the Python
workflow that turns those statistics into locus-level filtering decisions.
It is a research workflow repository, not a standalone Python package. The
workflow requires an external ASTER checkout and a locally built
`Afresh/bin/iils-statistics` executable.

## Method

For a fixed, annotated guide species tree, Afresh combines ASTER quartet/site
pattern statistics with the guide-tree branch annotations, simulates gene
trees under a multispecies coalescent null, calibrates thresholds, and writes
per-locus decisions. The resulting score measures weighted local topology
conflict relative to the guide tree. It is not an exact probability that a
locus was generated by incomplete lineage sorting, nor is it by itself proof
that a locus is paralogous.

## Requirements

- Linux or macOS with Python 3.12 or newer
- Python modules NumPy, SciPy, and DendroPy
- `make` and a C++17-compatible compiler
- ASTER source headers when building the native statistics executable
- ASTER `caster-site` when inferring a guide tree or rebuilding a tree after
  filtering

ASTER is an external dependency and is not included in this repository. Use a
compatible upstream checkout from <https://github.com/chaoszhang/ASTER>.
Afresh's native adapter includes ASTER headers and uses its tree and quartet
coloring implementations. The ASTER checkout's license and notices must be
reviewed together with the Afresh licensing terms before redistribution.

## Build

From the repository root, build the native statistics executable against an
external ASTER source tree:

```bash
make -C Afresh iils-statistics ASTER_DIR=/path/to/ASTER
```

The resulting executable is `Afresh/bin/iils-statistics`. The build reads ASTER
headers and does not modify the ASTER checkout. The executable is a local build
artifact and is not tracked.

## Inputs

The common filtering entry point is
`scripts/run_manifest_filter_pipeline.py`. It accepts either a locus list or a
tab-separated run manifest. Each locus-list row contains one path to an aligned
FASTA file. A guide tree must contain CASTER `s1`, `s2`, and `s3` annotations on
each scored internal branch. Alternatively, provide a constraint tree and
support-locus list so the workflow can infer a guide with `caster-site`.

A batch manifest requires `run_id` and `loci_file`. Optional columns include
`guide_tree`, `constraint_tree`, `support_loci_file`, `name_map`, and
`caster_seed`. Relative command-line and manifest paths are resolved from this
repository's root. Absolute paths can be used for data stored elsewhere.

## Run

After building the executable and preparing an annotated guide tree:

```bash
python scripts/run_manifest_filter_pipeline.py \
  --loci-file /data/loci.txt \
  --guide-tree /data/caster_support.tre \
  --out-root /results/example \
  --scratch-root /scratch/example \
  --aster-dir /path/to/ASTER \
  --statistics-bin Afresh/bin/iils-statistics \
  --n-gene-trees 50000 \
  --seed 43117
```

The default calibration simulates 50,000 gene trees. Reduce
`--n-gene-trees` for a small exploratory run. Use `--dry-run` to validate the
inputs and configuration without starting the analysis.

For several groups, provide `--run-manifest` instead of `--loci-file` and
`--guide-tree`. Each run writes a fresh result directory containing scores,
thresholds, locus decisions, retained-locus lists, logs, and a completion
receipt. Intermediate MSC banks remain in the private scratch directory and
are removed after a successful run. The command refuses to overwrite an
existing result path.

To export raw statistics without running calibration or filtering, use
`Afresh/bin/iils-statistics --help`. The Python materialization command is
`scripts/materialize_iils_statistics.py`. For an existing gene-tree score
table, `scripts/filter_iils_gene_trees.py` applies a rank-based removal rule
without rerunning statistics or calibration.

## Tests

After setting up the Python dependencies and building the native executable,
run the repository tests with:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Some native integration tests require `Afresh/bin/iils-statistics`. Tests do
not install dependencies or download ASTER automatically.
